## Fixed regression cases (`fixed_regressions.rs`)

Non-randomized, hand-picked, full-precision inputs and outputs, generated by running the actual implementation and pasted back into both this file and `whitepaper.md` Appendix A. Required cases, exact:

- `cpmm_regression_mispriced_pool()`: `x = dec!(1_200_000)`, `y = dec!(800_000)`, `fee_retention = dec!(0.997)`, `reference_price = dec!(0.60)`. Assert `optimal_size(...)` returns `Ok` and the exact `optimal_delta` value produced by the implementation, hard-coded as the assertion target.
- `cpmm_regression_no_arbitrage()`: same reserves, `reference_price = dec!(0.6725)`. Assert `Err(SizingError::NoArbitrageOpportunity)`.
- `stableswap_regression_balanced_3pool()`: `reserves = vec![dec!(10_000_000), dec!(10_000_000), dec!(10_000_000)]`, `amplification = dec!(100)`. Assert `solve_d()` returns `D` within `NEWTON_TOLERANCE` of `30_000_000` (the exact balanced-pool case, where `D = S` is the known analytic answer — this is the one StableSwap case with a checkable closed-form-equivalent, use it as the anchor regression).
- `stableswap_regression_imbalanced_3pool()`: `reserves = vec![dec!(15_000_000), dec!(8_000_000), dec!(9_500_000)]`, `amplification = dec!(100)`. Assert convergence within `MAX_NEWTON_ITERATIONS` and hard-code the resulting `D` from an actual run.
- `pmm_regression_woofi_reference()`: parameters taken from a worked example in WooFi v2's own published documentation (not invented) — pull the exact numbers from the source cited in `whitepaper.md § 11 [3]` during implementation, cite the specific example used in a code comment.

**Known gap (Session 4):** no complete numeric worked example could be found in WooFi's official docs, GitHub repo, or audit reports — only the symbolic formula (now in `whitepaper.md § 5.3.1`) and test-suite fragments missing the oracle setup needed to reproduce a full example. `pmm_regression_woofi_reference` as actually implemented uses a **synthetic** value (generated by running `sizing-core` itself, honestly labeled in the test's own doc comment) rather than fabricating a citation. Replace it if a genuine WooFi numeric example is later located — see `whitepaper.md` Appendix A for the exact values currently in use.

**Rule:** no value in this file may be computed by hand or estimated. Every assertion target is generated by running the code once, inspecting the output, and hard-coding that exact output as the regression target. This is what makes these "fixed regressions" rather than restated proptests — they catch behavior changes, not just algebraic errors.

## Property-based tests (proptest)

`proptest = "1.5"`, `proptest-derive` not required (no custom strategies beyond ranged decimals needed).

### `cpmm_proptest.rs`

| Property | Assertion |
|---|---|
| `prop_closed_form_matches_bisection` | For randomly generated `(x, y, f, P)` with `x, y ∈ [1, 1e12]`, `f ∈ (0.9, 1.0]`, `P ∈ (0, 10]`: `Cpmm::optimal_size` and `Cpmm::bisection_fallback` agree within `1e-4` relative tolerance whenever both return `Ok`. |
| `prop_global_optimum` | For the same generated inputs: sample 20 points around the returned `optimal_delta` (±1%, ±5%, ±10%) and assert `Profit` at every sampled point is `<= Profit(optimal_delta)`. |
| `prop_concavity_holds` | Assert `Profit''(Δx) < 0` (computed via finite differences) at 10 sampled points across the valid domain, for every generated input set. |
| `prop_no_arbitrage_detected_correctly` | For generated inputs where `f * y / x <= P`, assert `optimal_size` returns `Err(SizingError::NoArbitrageOpportunity)`, never a spurious `Ok`. |

### `stableswap_proptest.rs`

| Property | Assertion |
|---|---|
| `prop_newton_converges` | For randomly generated `reserves` (2-4 assets, each `∈ [1_000, 1e9]`) and `amplification ∈ [1, 5000]`: `solve_d()` returns `Ok` within `MAX_NEWTON_ITERATIONS`. |
| `prop_invariant_satisfied` | The returned `D` satisfies equation (6) in `whitepaper.md § 5.2` to within `NEWTON_TOLERANCE`. |
| `prop_convergence_failure_reported` | For deliberately pathological generated inputs (`amplification` set to exactly `dec!(0)` or below, or a reserve set to `dec!(0)`) constructed directly via `StableSwap::new`: assert `Err(SizingError::InvalidReserves)` is returned before Newton's method is attempted at all — this is a construction-time rejection, not a convergence failure, and the test must assert the specific variant. |

### `pmm_proptest.rs`

| Property | Assertion |
|---|---|
| `prop_unimodality_check_flags_known_bad_cases` | A hand-constructed, non-random set of `(base_reserve, quote_reserve, oracle_price, k)` combinations known to produce a non-unimodal profit function (constructed by hand specifically to violate unimodality, documented inline with a comment explaining why) — assert `check_unimodality` returns `false` for each. |
| `prop_golden_section_matches_grid_search` | For randomly generated well-behaved parameter sets (i.e., ones where `check_unimodality` returns `true`): assert the golden-section result agrees with a dense (10,000-point) grid search within `1e-4` relative tolerance. |
| `prop_iteration_count_matches_formula` | Assert the actual iteration count used equals the value predicted by equation (8) in `whitepaper.md § 5.3`, within ±1 (off-by-one from ceiling/floor boundary conditions is acceptable, more is not). |

### `net_profit_proptest.rs`

| Property | Assertion |
|---|---|
| `prop_domain_restriction_excludes_unprofitable_sizes` | `SizingResult.expected_profit` is always net of `fixed_cost` (per `API.md`, `NetProfit` is applied before a result is constructed). For all three curves, with randomly generated `fixed_cost > 0`: assert that whenever `optimal_size` returns `Ok(result)`, `result.expected_profit > Decimal::ZERO` strictly. Assert that when the entire domain is unprofitable net of `fixed_cost` (constructible by generating a `fixed_cost` larger than the curve's unconstrained maximum gross profit), `optimal_size` returns `Err(SizingError::NoProfitableSize)`. |
| `prop_max_size_respected` | For randomly generated `max_size`, assert `optimal_delta <= max_size` whenever `Ok` is returned. |

## Coverage expectations

- Every public function in `API.md` has at least one direct test (proptest or fixed regression) exercising it — not merely covered incidentally through another test.
- Every `SizingError` variant has at least one test that deliberately triggers it and asserts the specific variant, not just `is_err()`.
- `cargo tarpaulin` (or equivalent) target: 90%+ line coverage on `sizing-core`. Below this, name the uncovered lines explicitly in the PR description rather than silently shipping.

## Benchmark suite (not a unit test, but part of the testing contract)

`sizing-bench` produces `docs/benchmark-report.md`, regenerated (not hand-edited) on every run, containing:

- Wall-clock and iteration count: closed-form / Newton / golden-section vs. naive grid search at 10 / 100 / 1,000 / 10,000 grid points, for each of the three curve families.
- Accuracy-vs-grid-density table showing how many grid points a naive grid search needs before its answer converges to within `1e-4` of the guaranteed/closed-form answer.

## What to run before any PR

```bash
cargo test --workspace
cargo test -p sizing-core --test cpmm_proptest -- --test-threads=1
cargo test -p sizing-core --test stableswap_proptest -- --test-threads=1
cargo test -p sizing-core --test pmm_proptest -- --test-threads=1
cargo test -p sizing-core --test net_profit_proptest -- --test-threads=1
cargo test -p sizing-core --test fixed_regressions
cargo clippy --workspace -- -D warnings
cargo tree -p sizing-core | grep -Ei "reqwest|ethers|alloy|solana|tokio" && echo "FAIL: chain/network dependency leaked into sizing-core" && exit 1 || echo "PASS: sizing-core has no chain/network dependency"
```
